# Daily Football Impostor

Normal shows ten players from the source’s explicit correct/impostor lists. Select every match and submit once; omitted positives and selected impostors finish as a loss. One by One adds the optional extra-correct IDs, removes the same number of trailing impostors and still shows ten cards. Check one player at a time. Confirmed positives lock; the first impostor ends the round. Finding every positive wins.

The compiler verifies the selector contract and the general-player and dated-record imports. The app checks the local day index, exact source record, schemas, positive IDs, distinct lists, ten-card pools, portrait availability and explicit classifications. Reused record IDs are not unique daily identities: the date and full record/catalog enter the saved signature. Missing days requiring the source fallback reject fresh publication and retain the last good packet.

Native uniform shuffling replaces the source’s biased random comparator; order is random rather than a shared daily answer and survives relaunch. The three-column board uses large faces with 16-point corner marks. A sticky category clue keeps its artwork and name visible during scrolling. Artwork matches a unique complete category title in the seed library, supplying only visuals; it never imports memberships or joins player IDs. The practice country game remains separate.

Normal immediately shows confirmed, missed and wrongly selected players after submission. One by One marks the selected impostor and offers an explicit reveal of missed source matches after losing. Empty checks are disabled in the UI; the core safely handles Normal’s empty submission as a loss and rejects One by One’s empty check instead of reproducing the source crash. Confirmed players cannot be selected again. Wins grant streak credit once; losses and reveals do not. Practice gaps preserve source player identities, and missed One by One matches are recorded only after reveal.

A reviewed correction registry is defined in `content/futbol11-data-corrections.json`, initially empty. Future entries must include a UUID, complete source record ID/title/lists, removed extra IDs, exact full player names, review date, explanatory note and HTTPS evidence. The compiler rejects mismatched records or names before publication. The native loader verifies the same relationships and that playable extras are exactly raw extras minus reviewed removals. Raw source extras remain available for inspection. An active review adds a concise explanation and source links to the game.

Numeric identities from different catalogs are never interchangeable. Current general ID 113 is Kepa Arrizabalaga. A proposed review mistakenly associated that ID with César Azpilicueta; the exact-name guard rejected it before publication. Both pipeline and native regressions cover this wrong-identity rejection. Athletic’s official profile confirms Kepa’s club history: https://www.athletic-club.eus/en/players/kepa-arrizabalaga-revuelta/.

The current packet enables fourteen daily adapters. Fixed-date tests cover both exact win paths, one-shot misses, first-error losses, saved partial selections/order, terminal results, post-loss reveal, cross-catalog review rejection and single completion credit. Simulator flows verify both wins and both loss styles.
