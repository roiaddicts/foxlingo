# Daily Bingo Retro

A daily 3×4 board uses four `club`, two `club2`, three `country`, one `award`, one `continent` and one `other` category. Each type is shuffled with the source's MM/DD/YYYY seed before slicing; the combined board uses that seed again. The compiler pins the complete selector program and binds the legend table to its source module. No downloaded JavaScript is executed.

The separate catalog has 251 source-listed legends and 58 current category definitions. Explicit membership lists alone determine acceptance; IDs never join general or XI player catalogs. Historical membership IDs without a current category definition remain uninterpreted. Every selected category has a source-listed match. Category titles, portraits and artwork retain source scope; country membership follows the represented country in the catalog.

Players are offered randomly. Each correct placement draws another; the same legend can appear and be used again, matching the source. Skips count toward a randomly sampled threshold from five through twelve. At that threshold the next offer fits at least one unfilled category, the counter resets and a new threshold is sampled. Correct placement resets the skip counter. Wrong or filled-category taps do not advance the offer. Native uniform random sampling replaces the source's random-string shuffle for the assisted draw while preserving the eligible pool and help timing.

Untimed, 60-second and 90-second rounds are available. Timed rounds use a persisted wall-clock deadline; the clock continues while the learner leaves the screen or app. This makes expiration predictable across relaunch instead of depending on browser interval throttling. Expiration is checked before any move, so a late placement cannot turn a loss into a win. Untimed rounds do not expire. Offers, placements, skip threshold, timer, mistakes and session identity are saved atomically. Only all twelve placements grant win/streak credit, once. Saved completed wins recover credit if the app stopped before recording it. Losses grant none.

The board uses large category artwork, player portraits after placement and a small category overlay. Hold a category to inspect its title. Completed rounds let the learner browse source-listed matching legends. Wrong player/category pairs persist after completion with their source names and IDs. Short legend names do not automatically join canonical lesson subjects; player recommendations need a reviewed identity crosswalk. Unfilled categories may recommend existing lessons about that club or country; absent authored facts do not create new lesson claims.

Core tests cover source selection, namespaces, explicit acceptance, repeated legends, skip help for the last open category, timers, late moves, save recovery, malformed progress and altered catalogs. Python checks compilation against the archived source. Simulator tests cover wrong feedback, skip, a saved offered player, the final placement, completed-round relaunch and timed expiration across relaunch. The final-placement simulator test stages eleven legal source placements; the core test exercises the entire twelve-placement win.

Run `swift test` and `python3 -m unittest discover -s scripts -p 'test_*.py'`. Xcode UI checks are `FlowTests/testDailyBingoRetroWrongSkipResumeAndWin` and `FlowTests/testDailyBingoRetroTimerExpiresAcrossRelaunch`.

Native coverage is nineteen modes. Nine modes consume the published daily packet; ten existing modes still need their daily adapters. The verified refresh pipeline extracts all nineteen and preserves the previous good package on download/verification failure. Public feed hosting is not configured.
